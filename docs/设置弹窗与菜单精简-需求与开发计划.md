# 设置弹窗与菜单精简 — 需求梳理与开发计划

> 状态：开发完成（2026-11-18），入口设计已与用户确认
> 范围：前台/后台共用的设置组件、前台全屏菜单、通知接口与通知列表页。
> 前置：当前工作区已落地的「改密码整合进设置抽屉 + 个人中心居中」改动需先提交，作为本计划基线。

> **入口设计确认（2026-11-18）**：用户选定**方案 A——单汉堡聚合**，替代本计划 §1.4 R1/R3 的双按钮方案。要点：
> - 右上角只保留一个汉堡按钮（承载未读角标），**不再单独保留齿轮按钮**（覆盖 R3「齿轮入口保留」）。
> - 登录态菜单保留「通知」「设置」两项，点击直接打开全屏设置弹窗并定位到对应 tab（覆盖 R1「菜单删通知」）；菜单不再有「后台」。
> - 默认 tab 由菜单入口显式指定，不做「未读>0 进通知」的动态判断（原 R3 动态默认 tab 不再需要）。
> - 其余 R2/R4–R9、全屏弹窗视觉与行为按本计划执行。

## 一、产品需求梳理

### 1.1 背景

当前信息架构有三处不顺畅：

1. 全屏菜单里同时挂了「通知」和「后台」——通知在设置抽屉内已有独立 tab，重复入口；后台属于低频管理动作，却在最高频的主菜单里占位。
2. 设置抽屉是 20rem 宽的下拉浮层，承载「认证 / 推荐 / 专属链接 / 名片 / 修改密码 / 通知列表」六块内容，空间拥挤、长列表滚动体验差，移动端更明显。
3. 「修改密码」作为低频操作，常驻展开占用面板近半高度。

评审（§1.7）另发现三处会在上线后被立刻感知的缺口：通知 tab 只列未读、与通知页行为不一致；管理员入口可发现性下降；通知历史被 20 条截断。

### 1.2 目标

- 菜单只保留最高频入口；低频/管理功能收进设置。
- 设置从「小抽屉」升级为「全屏弹窗」，承载能力与移动端体验对齐菜单弹窗。
- 密码修改默认折叠；通知与分享路径补上最短操作。

### 1.3 需求清单

| ID | 需求 | 说明 | 优先级 |
|---|---|---|---|

| R2 | 菜单弹窗删掉「后台」，迁到设置弹窗 | 入口常驻设置弹窗 tab 栏右侧「后台 →」，仅管理员可见；后台布局内不显示（避免自指） | P1 |

| R4 | 修改密码折叠 | 默认收起，点标题展开；成功后显示「已更新 ✓」，3 秒后自动收起 | P2 |

| R9 | 改密后其他设备下线 | 启用 `AuthenticateSession` 中间件 + `logoutOtherDevices`，当前会话保持登录 | P1 |

### 1.4 交互细则

#### R1/R2 菜单弹窗（`layouts/app.blade.php`）

登录后菜单项从 5 项变为 3 项：

| 现状 | 调整后 |
|---|---|
| 智库 | 智库 |
| 后台（仅管理员） | —（迁至设置弹窗 tab 栏） |
| 个人中心 | 个人中心 |
| 通知 | —（删） |
| 退出账户 | 退出账户 |

- 未登录菜单（登录 / 加入）不变。
- 菜单弹窗的结构、尺寸、关闭按钮、动画、ESC 关闭均不变。
- 后台布局菜单（`layouts/admin.blade.php`）本就无「通知」「后台」入口，不动。

#### R2 后台入口（设置弹窗 tab 栏右侧）

```
┌────────────────────────────────────────────┐
│ SIGNIFY · 设置                     [✕]     │
├────────────────────────────────────────────┤
│  设置   通知 ③              后台 →          │  ← 管理员才渲染
├────────────────────────────────────────────┤
│              内容区（可滚动）               │
└────────────────────────────────────────────┘
```

- 位置：tab 栏右侧，与「全部已读」同一容器，滚动时始终可见。
- 可见条件：`auth()->user()->is_admin && !request()->routeIs('admin.*')`，服务端 `@if` 渲染。
- 样式：`label-caption text-accent`，与现有链接一致。
- 通知 tab 同时显示「全部已读」时，两者按「后台 →｜全部已读」排列。

#### R3 全屏设置弹窗

```
┌────────────────────────────────────────────┐
│ SIGNIFY · 设置                    [✕]      │  顶部栏（border-b）
├────────────────────────────────────────────┤
│  设置   通知 ③                              │  tab 栏
├────────────────────────────────────────────┤
│                                            │
│        内容区（max-w-2xl 居中，可滚动）      │
│                                            │
└────────────────────────────────────────────┘
```

- 容器：`fixed inset-0 z-[200] bg-paper flex flex-col`。
- 顶部栏：左侧 `SIGNIFY · 设置`，右侧 44×44 关闭按钮（与菜单弹窗同款 ✕）。
- 内容区：`flex-1 overflow-y-auto overscroll-contain`，内部 `max-w-2xl mx-auto px-6 py-10`；不做跨组件 body class 联动。
- 默认 tab：**动态**——打开时拉取未读数，未读 > 0 进「通知」，否则进「设置」。用户点红点即看消息，不点红点时落在设置。
- 关闭：✕、ESC；全屏无「点击外部」语义。
- 齿轮按钮及其未读角标：位置、样式不变。
- 后台布局复用同一组件，行为一致；R2 入口在后台内隐藏。

#### R4 修改密码折叠

```
┌─ 修改密码                        [展开 ▾] ─┐
└──────────────────────────────────────────┘
```

- 默认收起，只显示标题行；点击展开输入区，箭头翻转；`aria-expanded` + `aria-controls`。
- 提交成功后：「密码已更新 ✓」保留 3 秒 → 清空输入 → 自动收起。
- 校验失败：保持展开并显示错误。
- 折叠状态不持久化；每次打开弹窗重置为收起。
- 提交成功时同步执行 R9（其他设备下线）。

#### R5 通知可达性与历史

- 设置弹窗通知 tab 底部固定「查看全部通知 →」，跳 `/notifications`。
- `/notifications` 改分页 15/页；未读数单独统计（不受分页影响）。
- 没有通知时列表页与 tab 均显示空态。

#### R6 复制名片链接

- 位置：设置 tab「名片」块，「查看我的名片 →」下方。
- 复制内容：`s.card_url`（后端已是绝对 URL）。
- 优先 `navigator.clipboard`（需安全上下文），失败回退 `textarea + execCommand`；成功后按钮文案变「已复制 ✓」2 秒，失败显示「复制失败」。
- 微信内需用户手势触发，按钮点击满足条件。

#### R7 编辑资料入口

- 位置：设置 tab 内容顶部，`text-center` 小链接「编辑资料 →」。
- 跳 `route('profile.show')`，与个人中心同一页面。

#### R8 通知 tab：「最近通知」

- 数据源改为最近 20 条（含已读），每条带 `read` 字段；已读条目 `opacity-60`、左侧色条隐藏。
- 点击未读条目：POST 标记已读 → 本地置为已读并递减角标 → 跳转；点击已读条目：直接跳转，不发请求。
- 未读数（齿轮角标、tab 角标）仍以 unread 接口为准，数据源不变。
- 空态文案改为「暂无通知」。

#### R9 改密后其他设备下线

- 在 `bootstrap/app.php` 的 web 中间件组追加 `Illuminate\Session\Middleware\AuthenticateSession`。
- `PasswordController::update` 更新密码后调用 `Auth::logoutOtherDevices($validated['current_password'])`。
- 当前会话保持登录；其他会话在下次请求时被登出。
- 滚动上线安全：未带 `password_hash_web` 的存量会话不会被误杀，中间件首次请求会写入。

### 1.5 不变量（本次明确不动）

- `/notifications/unread`、`/notifications/{id}/read`、`/notifications/read-all` 三个接口的契约不变。
- 推荐申请、专属链接、认证状态、名片展示逻辑与文案不动。
- 个人中心页面（`profile/edit.blade.php`）不动。
- 后台布局菜单不动。
- 未登录用户的右上角仅有汉堡入口，不变。
- 「退出账户」保留在菜单并保持红色。

### 1.6 已定决策

| 问题 | 结论 |
|---|---|
| 通知列表页入口移除后是否保留页面？ | 保留，并补分页 |
| 全屏弹窗动画？ | 不加，与菜单弹窗一致 |
| 组件改名？ | `settings/drawer` → `settings/modal`，JS `settingsDrawer` → `settingsModal`，仅 2 处引用 |
| 打开默认 tab？ | 由菜单入口显式指定（方案 A：通知→通知 tab，设置→设置 tab） |
| 设置/通知入口？ | 单汉堡聚合（方案 A）：右上角仅汉堡按钮承载未读角标，菜单内「通知」「设置」弹窗直达；无独立齿轮 |
| 后台入口位置？ | tab 栏右侧常驻，不在设置内容区 |
| 密码改后其他设备？ | 下线 |

### 1.7 评审结论与需求映射

| 评审发现 | 严重度 | 处置 |

- 弹窗接入 `history.pushState` / `popstate`、焦点陷阱。
- 新增第三个右上角铃铛按钮（移动端拥挤，保持齿轮 + 汉堡）。

**R8 最近通知接口**（抽取共享映射，消除与 `unread` 的重复）：

```php
public function unread(Request $request)
{
    return $this->payload($request->user()->unreadNotifications);
}

public function recent(Request $request)
{
    return $this->payload(
        $request->user()->notifications()->orderByDesc('created_at')->limit(20)->get()
    );
}

private function payload($notifications)
{
    return $notifications->map(fn ($n) => [
        'id' => $n->id,
        'kind' => $n->data['kind'] ?? null,
        'title' => $n->data['title'] ?? '',
        'body' => $n->data['body'] ?? '',
        'url' => $n->data['url'] ?? null,
        'created_at' => $n->created_at->diffForHumans(),
        'read' => ! is_null($n->read_at),
    ])->values();
}
```

路由：`Route::get('/notifications/recent', [NotificationController::class, 'recent'])->name('notifications.recent');`

**前端通知加载**：`loadUnread` 改名 `loadNotifications`，并行拉 recent（列表）与 unread（角标）：

```js
async loadNotifications() {
  try {
    const [recentRes, unreadRes] = await Promise.all([
      fetch(this.recentUrl, { headers: { 'Accept': 'application/json' } }),
      fetch(this.unreadUrl, { headers: { 'Accept': 'application/json' } }),
    ]);
    if (recentRes.ok) this.items = await recentRes.json();
    if (unreadRes.ok) {
      this.unread = (await unreadRes.json()).length;
      // pulse 逻辑保留
    }
  } catch (e) {}
},
```

点击：已读条目直接跳转；未读条目乐观置为已读并递减角标后跳转。

**R6 复制**：

```js

  const url = this.s.card_url;
  try {
    if (navigator.clipboard && window.isSecureContext) {
      await navigator.clipboard.writeText(url);
    } else {
      const ta = document.createElement('textarea');
      ta.value = url; ta.style.position = 'fixed'; ta.style.opacity = '0';
      document.body.appendChild(ta); ta.select(); document.execCommand('copy'); ta.remove();
    }
    this.copied = true;
    setTimeout(() => { this.copied = false; }, 2000);
```

### 3.5 风险

| 风险 | 触发 | 缓解 |
|---|---|---|
| 全屏弹窗与菜单弹窗抢 z-index | 两者都 `z-[200]` | 菜单打开时齿轮被全屏菜单覆盖，天然互斥；设置组件 DOM 在齿轮之后；P5 双入口实测 |
| 滚动穿透 | 移动端滚到边界继续滚 | 滚动容器 `overscroll-contain`，不动 body class |
| `AuthenticateSession` 影响存量会话 | 部署后老会话无 `password_hash_web` | 中间件对无该 key 的会话只写入不登出；上线后抽查一个老会话 |
| 改密接口在测试环境行为差异 | `logoutOtherDevices` 依赖 session guard | 测试环境跑通；双浏览器手工验证兜底 |
| 通知双请求增加轮询开销 | 每 60 秒同时拉 recent + unread | 数据量 ≤20，可忽略；如后续有压力再合并接口 |
| 剪贴板在微信内被限制 | 非安全上下文或权限拒绝 | `execCommand` 兜底 + 「复制失败」提示，不阻断查看名片 |
| 分页视图样式不一致 | Laravel 默认分页视图与站点风格不同 | 用 Tailwind 默认分页视图，回归时核对；必要时在 `AppServiceProvider` 指定 `pagination::tailwind` |
| 后台布局视觉不一致 | admin 布局无 footer、外壳不同 | 组件全屏使用 `bg-paper` 绝对定位，不依赖父容器；P5 双布局实测 |
| 改名遗漏引用 | 只改前台布局 | `grep -rn "settings\.drawer\|settingsDrawer" resources/` 清零 |
