# 路由僵化整治 — 开发计划

> 范围：仅 `routes/web.php` + `EntrepreneurController@show` 的路由/解析层，不动业务模型与模板。
> 三项独立改动 A/B/C，A→B 有顺序依赖，C 完全独立可并行。
> 日期：2026-11-11

---

## 0. 概览

| 项 | 内容 | 预计 |
|---|---|---|
| A | `show` 双入口解耦：路由策略不再泄漏进 controller | D1（关键路径） |
| B | `/u/{slug}` 正则排除纯数字，消除 `/u/9` 重复入口 | D1 末（依赖 A） |
| C | 公开读路径补 throttle，防 view_count 虚增 | 0.25 日（独立并行） |

```
A show解耦   ████████░░  D1上午    (关键路径)
B 正则收口   ░░░░░░██░░  D1下午    (依赖A的canonical排查)
C throttle   ██░░░░░░░░  独立      (随时)
```

**关键策略：** A 是核心。A 改完后 canonical/分享链接的生成路径会变，B 的正则才有意义——否则 B 单独上会把 `route('entrepreneurs.show', $id)` 生成的 `/u/{纯数字}` 直接打成 404。C 与 A/B 无交集，可先做或并行。

## 1. A — `show` 双入口解耦

> 目标：controller 不再 `$request->routeIs()` 反查路由名决定查询字段；两条路由各自承担语义，共享一个渲染出口。

### 现状

`routes/web.php`：
```php
Route::get('/u/{slug}', [EntrepreneurController::class, 'show'])
    ->name('entrepreneurs.show')
    ->where('slug', '[a-z0-9]+(?:-[a-z0-9]+)*');

Route::get('/entrepreneurs/{id}', [EntrepreneurController::class, 'show'])
    ->whereNumber('id');   // 无 name，SEO fallback
```

`app/Http/Controllers/EntrepreneurController.php:73`：
```php
public function show(Request $request, string $idOrSlug)
{
    $entrepreneur = Entrepreneur::when(
        $request->routeIs('entrepreneurs.show') && !ctype_digit($idOrSlug),
        fn ($q) => $q->where('share_slug', $idOrSlug),
        fn ($q) => $q->where('id', (int) $idOrSlug),
    )
        ->where(fn ($q) => $q->where('status', STATUS_APPROVED)->orWhere('user_id', Auth::id()))
        ->firstOrFail();
    $this->trackView($request, $entrepreneur);
    return view('entrepreneurs.show', ['entrepreneur' => $entrepreneur->load('user')]);
}
```

**僵化点：** controller 通过 `routeIs('entrepreneurs.show')` 反查路由名决定查询字段——路由结构绑架业务逻辑。再加一个短链入口就要改方法体；纯数字 slug 在两条路由间的归属也由 controller 而非路由层判定。

### 改法

**A.1 路由层分流**（`routes/web.php`）
```php
Route::get('/u/{slug}', [EntrepreneurController::class, 'showBySlug'])
    ->name('entrepreneurs.show')   // named route 仍指向 /u，route() 生成短链不变
    ->where('slug', '[a-z0-9]+(?:-[a-z0-9]+)*');  // B 项再排除纯数字

Route::get('/entrepreneurs/{id}', [EntrepreneurController::class, 'showById'])
    ->whereNumber('id');   // 仍无 name，SEO fallback
```

**A.2 controller 拆两个入口 + 共享渲染**（`EntrepreneurController.php`）
```php
public function showBySlug(Request $request, string $slug)
{
    $entrepreneur = Entrepreneur::where('share_slug', $slug)
        ->where(fn ($q) => $q->where('status', self::STATUS_APPROVED)->orWhere('user_id', Auth::id()))
        ->firstOrFail();
    return $this->display($request, $entrepreneur);
}

public function showById(Request $request, int $id)  // whereNumber 已保证 int
{
    $entrepreneur = Entrepreneur::where('id', $id)
        ->where(fn ($q) => $q->where('status', self::STATUS_APPROVED)->orWhere('user_id', Auth::id()))
        ->firstOrFail();
    return $this->display($request, $entrepreneur);
}

private function display(Request $request, Entrepreneur $entrepreneur)
{
    $this->trackView($request, $entrepreneur);
    return view('entrepreneurs.show', ['entrepreneur' => $entrepreneur->load('user')]);
}
```

**A.3 canonical 排查（B 的前置）**
`show.blade.php` 与分享链接处凡 `route('entrepreneurs.show', …)` 的调用点，逐个核：
- 传 `$entrepreneur->share_slug`（非空）→ `/u/{slug}`，正常。
- share_slug 为空时若 fallback 到 `route('entrepreneurs.show', $entrepreneur->id)` → 生成 `/u/{纯数字}` → **B 上线后会 404**。
- 改法：share_slug 为空时 canonical/og:url 改用 `url('/entrepreneurs/'.$entrepreneur->id)`（走无 name 的 id 路由），不走 named route。

### 依赖
- 无外部依赖。
- B 依赖 A.3 的 canonical 排查结论。

### 影响面 / 回归点
- 所有 `route('entrepreneurs.show', $slug)` 调用：named route 仍指向 `/u/{slug}`，**URL 输出不变**。
- `trackView` 私有方法签名不变，行为不变。
- 测试：现有 `entrepreneurs.show` 相关用例（slug 路径 + id 路径两套）必须全绿；`firstOrFail` 对不存在 slug/id 仍 404。

### 验收
- `EntrepreneurController` 内无 `$request->routeIs(` 调用。
- `grep -rn "routeIs" app/Http/Controllers/EntrepreneurController.php` 为空。
- `/u/{有效slug}` 200、`/u/{不存在slug}` 404、`/entrepreneurs/{有效id}` 200、`/entrepreneurs/{不存在id}` 404。
- 现有测试套全绿，无新增红。

## 2. B — `/u/{slug}` 正则排除纯数字

> 目标：纯数字只走 `/entrepreneurs/{id}`，消除 `/u/9` 与 `/entrepreneurs/9` 双 URL 指同一档案的 canonical 重复。

### 现状

`->where('slug', '[a-z0-9]+(?:-[a-z0-9]+)*')` —— `[a-z0-9]+` 含数字，纯数字 `"9"` 实测 `preg_match` 命中（已验证返回 1）。于是 `/u/9` 走短链路由，进入 `showBySlug`（A 之后）按 `share_slug='9'` 查询，查不到则 404——与 `/entrepreneurs/9` 是两条不同 URL 指向不同结果路径，canonical 重复。

### 改法

正则前加负向断言排除纯数字（`routes/web.php`）：
```php
->where('slug', '(?![0-9]+$)[a-z0-9]+(?:-[a-z0-9]+)*')
```
- `(?![0-9]+$)` 断言：剩余输入不是纯数字到结尾。
- 纯数字 `9`、`123` → 不匹配 → 落到 `/entrepreneurs/{id}`（`whereNumber`）。
- 含字母的 slug `huang-jiannan`、`artist-2` → 正常匹配。

### 依赖
- **A.3 必须先完成**：确认 share_slug 为空时 canonical/分享链接不传纯数字给 named route。否则 B 上线后，那些 `/u/{纯数字}` 链接变 404。

### 影响面 / 回归点
- 现有所有有效 slug 均含字母（人工名 slug），不受影响。
- 测试：若有用例直接打 `/u/9` 期望走 id 查询，会变红——这类用例本身就在测错误行为，应改为 `/entrepreneurs/9`。
- 线上微信分享历史链接：分享出去的都是 share_slug（含字母），无 `/u/{纯数字}` 形态，不受影响。

### 验收
- `php -r "var_dump(preg_match('/^(?![0-9]+$)[a-z0-9]+(?:-[a-z0-9]+)*$/', '9'));"` 返回 `int(0)`。
- 同正则对 `huang-jiannan` 返回 `int(1)`。
- `/u/9` 返回 404（或落到 id 路由 200，取决于路由顺序——当前 `/u` 在前 `/entrepreneurs/{id}` 在后，纯数字不匹配 `/u` 后会继续匹配 `/entrepreneurs/{id}`，返回 200）。
- `/u/{有效slug}` 200 不变。

## 3. C — 公开读路径补 throttle

> 目标：防爬虫/小程序高频请求虚增 view_count 与空耗列表查询。

### 现状

`/u/{slug}`（show，`trackView` 每视图 2 写：`increment` + `EntrepreneurView` 插入）与 `/entrepreneurs`（列表，分页 + industries pluck + cities pluck 共 3 查询，零缓存）**均无 throttle**。对比：`setup.install` 挂了 `throttle:5,1`、`batch-approve` 挂了 `throttle:30,1`——公开读路径反而没有。

`trackView` 已有会话级去重（同会话 24h 1 次），但那是防"刷新重复计"，不防"不同会话高频请求"（爬虫不带 cookie = 每次新会话）。

### 改法

`routes/web.php`：
```php
Route::get('/entrepreneurs', [EntrepreneurController::class, 'index'])
    ->name('entrepreneurs.index')
    ->middleware('throttle:60,1');

Route::get('/u/{slug}', [EntrepreneurController::class, 'showBySlug'])   // A 之后的方法名
    ->name('entrepreneurs.show')
    ->where('slug', '(?![0-9]+$)[a-z0-9]+(?:-[a-z0-9]+)*')               // B 之后的正则
    ->middleware('throttle:120,1');
```

- 列表 60/min：列表查询重（3 查询），给保守值。
- 详情 120/min：详情单查询 + 2 写，但用户可能连续翻看多个档案，放宽些。
- 桶前缀默认按 `domain|ip`（Laravel 默认），不含路由——**记忆里云乡项目踩过"全站共用一个桶"的坑**（`throttle:5,1` 桶键不含路由名导致 6 条路由共用计数器）。Laravel 11 默认 `throttle` 中间件已按路由名+IP 分桶（`RateLimiter::for` 默认键），但若项目自定义过 limiter 需核——本计划假设用默认 `throttle` 中间件，不自定义。

### 依赖
- 无。可与 A/B 并行，且不依赖 A 的方法名改动——若先于 A 上，方法名仍写 `show` 即可，A 落地时一并改。

### 影响面 / 回归点
- **测试影响：** Laravel 测试环境下 `throttle` 中间件在 `runningUnitTests()` 时行为需核——若测试连续打多个请求触发限流，用例会假红。记忆：`VerifyCsrfToken` 在测试整体跳过，throttle 无此全局豁免。解法：测试里用 `Route::withoutMiddleware(['throttle'])` 或在 `pest`/`TestCase` 中对限流路由解绑，或用 `throttle:60,1` 高到测试跑不爆。**先跑测试确认是否误伤，再定阈值。**
- 真人浏览：60/min 远超人工点击速率，无感知。
- SEO 爬虫：Googlebot 单域爬取速率通常 <60/min，不撞；恶意爬虫会被挡——符合预期。

### 验收
- 连续 61 次 `GET /entrepreneurs` 第 61 次返回 429（用 `curl` 循环实测，或测试 `assertStatus(429)`）。
- 连续 121 次 `GET /u/{slug}` 第 121 次返回 429。
- 现有测试套全绿（若限流误伤测试，按"影响面"方法解绑）。
- `x-ratelimit-limit` 响应头存在。

## 4. 顺序与合流

```
C throttle ──┐（独立，随时）
             │
A show解耦 ──┼── A.3 canonical 排查 ── B 正则收口 ── 全量回归
             │
             └─ A.1/A.2 落地
```

- A 与 C 完全并行。
- B 必须等 A.3（canonical 排查）完成，否则可能把分享链接打成 404。
- 三项全部落地后跑一次全量测试 + `curl` 端到端验 `/u/{slug}` / `/u/{纯数字}` / `/entrepreneurs/{id}` / 429。

## 5. 不做（明确排除）

- `/entrepreneurs/{id}` 无 name 的 SEO fallback：**保留不动**（有意不 301，避免微信预览读目标 URL）。
- `notifications/{id}` 改 route model binding：D 项（轻微），本期不做。
- `setup.php` 已安装后从路由表移除：E 项（可缓），本期不做。
- `/my/profile` 单例 POST=create 语义：Breeze 风格遗留，不动。
- 列表查询缓存：C 只加 throttle，不引入缓存层（缓存是独立议题）。

## 6. 风险

| 风险 | 触发 | 缓解 |
|---|---|---|
| B 把线上分享链接打成 404 | A.3 漏排查某个 canonical/分享调用点传了纯数字 | B 上线前 `grep -rn "route('entrepreneurs.show'" resources/ app/` 逐点核 |
| throttle 误伤测试 | 测试连续打限流路由 | 先跑测试，必要时 `withoutMiddleware` |
| `showBySlug`/`showById` 拆分后 trackView 行为漂移 | 重构时 `display()` 私有方法漏传参 | trackView 有本人浏览豁免逻辑，回归测试须覆盖"本人浏览不计"+"访客浏览计"两条 |
