# 兰台工作台合并 — 需求与开发文档

> 状态：设计定稿，待开发
> 日期：2026-11-03
> 范围：将兰台观局情报产出接入 Signify，企业家登录后自助浏览；兰台 Laravel 站点整体退役，Python 内核作为外部流水线保留。

---

## 1. 背景与目标

Signify 是企业家智库目录（Laravel 11 + Blade + Alpine，SQLite，vour.cn）。兰台观局是政策情报工作站（Python 五阶段内核 + 独立 Laravel 站）。

**目标**：企业家在 Signify 内直接浏览兰台产出的政策情报，不再维护第二套 Web 应用。

**核心决策（本期锁定）**：

| 决策 | 结论 | 理由 |
|---|---|---|
| 兰台 Laravel 后端 | **退役** | Signify 是唯一 Web 应用，避免双 auth / 双布局 |
| 报告存储 | **JSON 文件，不进数据库** | 兰台现状即 `report.json` 落盘，保留现状零迁移 |
| 双轨出刊 | **保留，A 方案（两份文件、跑两次）** | 不动 `publish()` / `Report` 契约 |
| 核验闭环 | **保留（自动口径回查附录）** | P2.5 已自动化，零人工 |
| 人工审核 | **砍掉** | 运营负担过重；自动核验附录为唯一质量兜底 |
| LLM | **sensenova 测试期，后续可换** | Python 侧抽 provider 接口，schema 不变则 Signify 零感知 |

## 2. 架构总览

```

│  P2 采集 → P2.5 核验 → P3 抽取 → P4 研判 → P5 出刊         │
```

**耦合点只有三个**：

## 3. 明确不做的事

- **不建数据库表**：报告正文、审核状态都不进 DB。无 `lantai_reports`、无 `lantai_reviews`。
- **不做审核队列 / 草稿暂存**：无 `_draft/` 区，Python 产出即发布，企业家直接可见。
- **不保留兰台 Laravel 站点**：安装向导、dashboard、信源后台全部丢弃。
- **不改 `publish()` 签名与 `Report` 契约**：双轨靠 runner 调两次，不靠契约承载双轨。
- **不做 Python ↔ Signify 的运行时调用**：无 API、无 webhook，纯文件耦合。

## 4. 数据契约：Report JSON

兰台 `Report.to_json()`（`pipeline/contracts.py:117`）已定义，**Signify 按此只读消费，不改字段**：

```json
{
  "period": "20261027-20261102",
  "title": "…",
  "summary": "…",
  "kind": "brief",            // "brief" | "full"
  "generated_at": "2026-11-03T08:12:00+00:00",
  "source_count": 12,          // 去重源 URL 数
  "domains": ["投资", "消费"], // 九类领域标签，订阅匹配轴之一
  "regions": ["全国", "广东"], // 地区口径：全国 / 省级行政区名 / 县域 / 地区
  "content_md": "## 核心摘要 …" // 完整 Markdown 正文（含核验附录）
}
```

字段语义：
- `period`：区间标识，`YYYYMMDD-YYYYMMDD`，文件归属与列表排序的键。
- `kind`：`brief`（无数据表，只给判断）或 `full`（brief + 精选数据表 + `<details>` 折叠完整台账）。两轨 `title`/`summary`/`domains`/`regions` 相同，仅 `content_md` 深度不同。
- `content_md`：已含核验附录（P2.5 产出，见 §7），Signify 直接渲染不参与核验。
- `domains`/`regions`：订阅匹配两轴，见 §8。

**Signify 侧只读，不写、不解析 `content_md` 内部结构**——整体作为 Markdown 渲染。`<details>` 标签由前端默认折叠。

## 5. 文件落点与发现

### 5.1 落点

Python `DATA_DIR`（`pipeline/config.py`）指向 Signify 存储区：

```
storage/app/lantai/reports/{period}/
  ├── report-brief.json      ← Signify 读
  ├── report-full.json       ← Signify 读
  ├── report-brief.md        ← 旁路产物，Signify 不读
  ├── report-full.md         ← 旁路产物，Signify 不读
  ├── ledger.json            ← 旁路，Signify 不读
  ├── analysis.json          ← 旁路，Signify 不读
  ├── verify.json            ← 旁路，Signify 不读（核验已拼进 content_md）
  ├── raw/                   ← 旁路，体量最大
  └── run.log
```

Signify 只 glob `report-brief.json` / `report-full.json`，其余文件忽略。`raw/` 有体量，由 Python 侧 cron 按期清理（保留近 N 期），不影响 Signify。

### 5.2 发现机制（Signify 侧）

`LantaiReportService`（§9）扫描 `storage/app/lantai/reports/*/report-brief.json`，读 `period`/`title`/`summary`/`domains`/`regions`/`generated_at` 出列表。详情页按 `period` 读两份 JSON，传给视图。

低频直接读盘；流量上来后用 Laravel cache 缓存「文件索引」，按目录 mtime 失效。MVP 不做缓存。

## 6. 双轨出刊机制

### 6.1 现状（不改）

- `publish(analysis, ledger, raw_items, period, kind=...)`：一个 `kind` 出一份报告，`kind` 默认 `brief`。
- `run.py` 一次执行传一个 `--mode`，写一份 `report.json` 到 `DATA_DIR/{period}/`。
- 默认派生：`≤7 天 brief，>7 天 full`（`run.py:69`）。

### 6.2 本期改动（run.py 两行）

`run.py:174-175` 写盘路径带上 `kind`：

```python
# 改前
report_path = out_dir / "report.md"
report_meta_path = out_dir / "report.json"
# 改后
report_path = out_dir / f"report-{kind}.md"
report_meta_path = out_dir / f"report-{kind}.json"
```

`publish()`、`Report`、`contracts.py`、模板——全部不动。

### 6.3 双轨 cron 模式

同一期出两轨，跑两次，第二次复用第一次的中间产物：

```bash
# 第一次：完整流水线，产 brief + ledger/analysis/verify
python pipeline/run.py --days 7 --mode brief

# 第二次：--republish 跳过 P2/P3/P4/P2.5，只重跑 P5，产 full
python pipeline/run.py --days 7 --mode full --republish
```

**双烧 LLM 的真实成本**（用户已接受）：
- P4 研判（重 LLM 调用，三维交叉判断）：**只跑一次**，结果存 `analysis.json`，第二次 `--republish` 复用。
- P5 `_llm_title_summary`（轻 LLM 调用，生成标题+摘要）：**跑两次**，两轨各一次。这是唯一的双烧点，单次 `max_tokens=800`，成本小。
- P2.5 核验：只跑一次（随 brief 完整流水线），`verify.json` 被 full 的 P5 读取。

> 两轨 `title`/`summary` 实际相同，第二次 LLM 调用是冗余的。若日后想省掉，可在 `run.py` 的 `--republish` 分支里把第一次的 title/summary 注入第二次 `publish()`——但那要改 `publish()` 签名，本期不做，接受双烧。

### 6.4 月报同理

```bash
python pipeline/run.py --from 2026-10-01 --to 2026-10-31 --mode brief
python pipeline/run.py --from 2026-10-01 --to 2026-10-31 --mode full --republish
```

## 7. 核验闭环（自动，保留）

P2.5 步骤（`run.py:122-130`）：
1. 按 当期台账主要领域派生口径词。
2. 回查发改委 / 文旅等官方源（`p2_verify_all.verify_from_ledger`）。
3. 命中写 `verify.json`，去重。
4. P5 `_render_verify(period)` 读 `verify.json`，按关键词分组渲染成「官方核验参考」附录，拼进 `content_md`，上限 20 条。
5. `verify.json` 缺失 / 损坏 / 无命中 → 占位文本，**不阻断出刊**。

**对 Signify 完全透明**：核验附录已是 `content_md` 的一部分，Signify 整体渲染即可，无需识别或处理。

网络失败时核验附录为空——这是裸跑（§12）下唯一的质量兜底，cron 监控应关注 `verify.json` 是否持续为空。

## 8. 区域与领域映射

### 8.1 兰台 region 体系（`regional/constants.py` + `p3_extract.py:197`）

- 省级 31 = 27 省 + 4 直辖市（北京/天津/上海/重庆）。
- 副省级 15 城（哈尔滨/长春/沈阳/大连/济南/青岛/南京/宁波/杭州/厦门/武汉/广州/深圳/成都/西安）。
- 报告 `regions` 字段取裸名：「全国」「广东」「宁夏」……封闭类别 `全国`/`县域`/`地区` 不参与剥离。
- region key 体系：`P{行政码}`（省）/ `M{码}`（直辖市）/ `S{码}`（副省级），用于 `regional/` 资产，**pipeline 报告的 `regions` 字段不用 key、用裸名**。

### 8.2 Signify 侧映射

Signify `Entrepreneur.city` 是自由文本（「深圳」「深圳市」「广东深圳」）。需一张 **城市 → 省级裸名** 查找表：

```
深圳 → 广东
宁波 → 浙江
青岛 → 山东
…
```

`config/lantai_regions.php`（新增）维护此映射，键为常见城市写法，值为兰台裸名。未命中时回退到 `city` 原值做模糊匹配，再回退到「全国」。

### 8.3 匹配规则（企业家看到哪些报告）

工作台列表过滤（`LantaiReportService::matchesEntrepreneur`）：
- 报告 `regions` 含「全国」→ 所有人可见。
- 报告 `regions` 含企业家的省级裸名 → 可见。
- 报告 `domains` 与企业家 `industry` 的领域映射相交 → 可见（领域轴，可选，MVP 可先不做）。
- 其余报告可浏览但不在「与我相关」默认视图里（提供「全部」切换）。

> 兰台 `regional/` 模块另有省级产业集群卡 / 判决 / 横向对标等**区域资产**（`regional/data/`，按 `P{码}`/`S{码}` key 组织，季度刷新）。本期工作台**不纳入**区域资产，仅接 pipeline 双轨报告。区域资产接入留作后续 phase（§13 P3）。

## 9. Signify 侧开发

### 9.1 路由

```php
// routes/web.php，auth 组内新增
Route::middleware(['auth', 'workbench.access'])->prefix('workbench')->name('workbench.')->group(function () {
    Route::get('/', [WorkbenchController::class, 'index'])->name('index');
    Route::get('/report/{period}', [WorkbenchController::class, 'show'])
        ->where('period', '[0-9]{8}-[0-9]{8}')->name('show');
});
```

`workbench.access` 中间件：`auth` + `auth()->user()->entrepreneur` 存在且 `status === 'approved'`。不满足 → 403 或重定向个人中心提示「收录后可浏览工作台」。

### 9.2 LantaiReportService

`app/Services/LantaiReportService.php`：

- `list(): array` — glob `storage/app/lantai/reports/*/report-brief.json`，逐份 `json_decode` 取 meta（不取 `content_md`），按 `period` 降序返回。
- `find(string $period): ?array` — 读 `report-brief.json` + `report-full.json`，返回 `['period', 'brief_md', 'full_md', 'meta']`。任一缺失返回 null（404）。
- `matchesEntrepreneur(array $reportMeta, Entrepreneur $e): bool` — §8.3 规则。

文件不存在 / JSON 损坏 → 抛 `LantaiReportNotFoundException`，控制器转 404 或友好提示「该期情报暂不可用」。

### 9.3 控制器与视图

`app/Http/Controllers/WorkbenchController.php`：
- `index` → `LantaiReportService::list()`，按 `matchesEntrepreneur` 分「与我相关」/「全部」两组，传给视图。
- `show` → `LantaiReportService::find($period)`，传 `brief_md` + `full_md` + meta。

`resources/views/workbench/index.blade.php`：列表，每条显示 `period` / `title` / `summary` / `regions` 标签。
`resources/views/workbench/show.blade.php`：

```html
<div x-data="{ track: 'brief' }">
  <button @click="track = 'brief'" :class="track === 'brief' ? ...">简报</button>
  <button @click="track = 'full'" :class="track === 'full' ? ...">详报</button>
  <div x-show="track === 'brief'">{!! $brief_md !!}</div>
  <div x-show="track === 'full'" x-cloak>{!! $full_md !!}</div>
</div>
```

`content_md` 渲染走 Markdown 解析（Signify 已有的渲染路径，若无则用 `league/commonmark` 或 `Str::markdown`）。`<details>` 由浏览器原生折叠。

### 9.4 入口

个人中心 `/my/profile` 或顶部导航，对 approved 企业家显示「工作台」入口。游客、pending/rejected 不可见。

### 9.5 通知联动（可选，后置）

Python 写完新报告后，可调 Signify 通知 API（§已建 `notifications/unread` 体系）给该 region 企业家推「你的行业有新政策情报」。需 Python 侧调 Signify HTTP 端点 + Signify 侧加接收路由。**本期不做**，留作增强。

## 10. Python 侧开发

### 10.1 LLM provider 接口（为换模型铺路）

`pipeline/llm.py` 现有 `chat_json()` 直连 sensenova。抽成 provider 接口：

```python
# pipeline/llm.py 目标形态
class LLMProvider:
    def chat_json(self, messages, max_tokens=...) -> dict | None: ...

class SenseNovaProvider(LLMProvider): ...   # 现实现搬入
class XxxProvider(LLMProvider): ...         # 后续换型时新增

# config/env 选 provider
PROVIDER = os.getenv("LANTAI_LLM_PROVIDER", "sensenova")
```

**约束**：任何 provider 必须返回与现状同结构的 JSON（`title`/`summary` 等），否则 P5 渲染崩。这是 provider 契约，不是 Signify 契约。换模型只改 `llm.py` + env，不动其他模块。

### 10.2 run.py 写盘路径

§6.2 两行改动。

### 10.3 DATA_DIR 指向

`pipeline/config.py` 的 `DATA_DIR` 改为读 env，默认仍 `pipeline/data/`，生产指向 Signify `storage/app/lantai/reports/`：

```python
DATA_DIR = Path(os.getenv("LANTAI_DATA_DIR", str(Path(__file__).parent.parent / "data")))
```

### 10.4 cron

```cron
# 每周一 08:00 出上周双轨
0 8 * * 1 cd /path/lantai && python pipeline/run.py --days 7 --mode brief && python pipeline/run.py --days 7 --mode full --republish
```

同服部署则直接写 Signify storage；分离部署则 cron 后追加 rsync 同步 `report-*.json` 到 Signify。

## 12. 风险与兜底

### 12.1 sensenova 测试期裸跑

人工审核砍掉后，sensenova 原始产出 + 自动核验附录直接到企业家眼前。核验附录是**唯一质量兜底**——它回查官方源，但本身不判定 LLM 判断的对错，只提供对照参考。

**缓解**：
- 上市前换更强模型（§10.1 provider 接口已铺路）。
- cron 监控 `verify.json` 持续为空 / `analysis.json` 研判为空（`run.py:159` 的静默失败检测）告警。
- 若上市前评估仍不够，可在 Signify 侧加回轻量审核层（`_draft/` 暂存 + admin 发布开关），**A 方案下这是文件搬运，不碰 Python 契约**——门留着，本期不开。

### 12.2 文件耦合的脆性

- Python 写盘与 Signify 读盘无锁，理论上存在读到半写 JSON。`LantaiReportService` 读失败回退 404，不崩。
- schema 漂移：Python 改 `to_json()` 字段而 Signify 未跟 → 渲染异常。靠 `schema_version` 字段（未来加）或测试（§14）兜。

### 12.3 raw/ 体量

`storage/app/lantai/reports/{period}/raw/` 累积增长。Python 侧 cron 保留近 N 期、清旧期。Signify 不读 raw，但占盘需控。

## 14. 验收标准

**P1 Signify 侧**：
- approved 企业家进入 `/workbench` 看到报告列表；pending/rejected/游客被挡。
- 「与我相关」按 `regions` 含企业家省级裸名或「全国」过滤；「全部」显示所有期。
- 详情页 brief/full 切换瞬时无刷新；full 的 `<details>` 默认折叠。
- `period` 不存在或 JSON 损坏 → 友好 404，不 5xx。
- Feature 测试覆盖以上路径全绿。

**P2 Python 侧**：
- `--mode brief` 与 `--mode full --republish` 各产一份 `report-{kind}.json`，路径正确。
- `--republish` 不重跑 P2/P3/P4/P2.5，`analysis.json`/`verify.json` 复用。
- `LANTAI_DATA_DIR` env 生效，产出落到 Signify storage。
- `LANTAI_LLM_PROVIDER=sensenova` 与默认行为一致；切其他 provider 不报错（返回结构同）。
- 现有 166 Python 测试全绿（契约未动）。

**端到端**：
- 本地灌入一期真实双轨 JSON，企业家账号登录 `/workbench` 看到该期、切换 brief/full、核验附录可见。
