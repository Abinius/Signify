## 1. P1 — 改密码

> 目标：登录用户在个人中心能改密码；当前 `PUT /password` 路由 + `PasswordController::update` 完整但无 UI。

### 现状

`app/Http/Controllers/Auth/PasswordController.php`（完整，不动）：
```php
public function update(Request $request): RedirectResponse
{
    $validated = $request->validate([
        'current_password' => ['required', 'current_password'],
        'password' => ['required', 'confirmed', Password::min(6)],
    ]);
    $request->user()->update(['password' => Hash::make($validated['password'])]);
    return back()->with('status', '密码更新成功');
}
```

`routes/auth.php`：`PUT /password` name=`password.update` 已注册。✓

`resources/views/profile/edit.blade.php`：外层 `x-data="profileUpload(...)"` 包整页（:13），`@else` 分支一个大 form（:36–217，PATCH `profile.update`）。**无改密码表单。**

### 改法

**P1.1 表单插入**（`profile/edit.blade.php:217` 之后、`:218 @endif` 之前）

在大 form `</form>`（:217）之后插入独立 section——**不进 profile.update 的 form**（不同 action：改密码是 `PUT /password`）：
```blade
{{-- 修改密码：独立表单，不与档案编辑混提交 --}}
<div class="mt-10 border border-hairline bg-surface p-10">
  <h2 class="font-display text-display-md font-bold text-ink mb-2">修改密码</h2>
  <p class="text-sm text-muted mb-8">需先验证当前密码。</p>
  <form method="POST" action="{{ route('password.update') }}" class="max-w-md space-y-6">
    @csrf
    @method('PUT')
    <div>
      <label class="label-caption text-muted">当前密码</label>
      <input type="password" name="current_password" required autocomplete="current-password" class="input-line">
      @error('current_password') <p class="field-error">{{ $message }}</p> @enderror
    </div>
    <div>
      <label class="label-caption text-muted">新密码</label>
      <input type="password" name="password" required autocomplete="new-password" class="input-line">
      @error('password') <p class="field-error">{{ $message }}</p> @enderror
    </div>
    <div>
      <label class="label-caption text-muted">确认新密码</label>
      <input type="password" name="password_confirmation" required autocomplete="new-password" class="input-line">
    </div>
    <button type="submit" class="btn-ink">更新密码</button>
  </form>
</div>
```

**P1.2 成功提示**：`PasswordController` 返回 `back()->with('status', '密码更新成功')`。`layouts/app.blade.php:113` 已 `@include('components.flash')`——确认 flash 组件渲染 `session('status')`，若只渲染 `error`/`success` 需补 `status` 分支。

### 依赖
- 无。controller + 路由已就绪。

### 影响面 / 回归点
- 外层 Alpine `profileUpload` 组件不操作密码字段，放其内无副作用（独立 form，不同 action）。
- `current_password` 规则 Laravel 8+ 内置，无需自造。
- users 表 password 列已兼容 bcrypt（Breeze 默认），无迁移。
- `confirm-password`（敏感操作确认）与改密码无关，不碰。

### 测试
新建 `tests/Feature/PasswordUpdateTest.php`，2 用例：
1. **正确当前密码改密成功**：actingAs → POST（PUT）`/password` 带正确 current_password + 新密码 + confirmation → assertRedirect + DB 里 password 已变（`Hash::check` 新密码）。
2. **错误当前密码被拒**：同上但 current_password 错 → assertSessionHasErrors('current_password')。

### 验收
- 登录用户在个人中心可见"修改密码"区块。
- 正确当前密码 → 提交后密码更新、flash 显示"密码更新成功"。
- 错误当前密码 → 表单回显错误、密码不变。
- 新测试 2 用例绿 + 现有套全绿。

## 2. P2 — 通知列表页

> 目标：登录用户有可访问的通知列表页；当前 `/notifications` 返回 JSON、无 UI 入口。

### 现状

`app/Http/Controllers/NotificationController.php:9`：
```php
public function index(Request $request)
{
    return $request->user()->notifications()
        ->orderByDesc('created_at')->limit(20)->get()
        ->map(fn ($n) => ['id'=>..., 'kind'=>..., 'title'=>..., 'body'=>..., 'url'=>..., 'read_at'=>..., 'created_at'=>...])
        ->values();   // 返回 JSON
}
```

`unread`/`markRead`/`markAllRead` 三个 AJAX 端点完整，设置抽屉 `<x-settings.drawer />` 在用。**`index` 的 JSON 无人调用**（已核：`grep /notifications` 在 `public/js/`、`resources/` 无命中，排除 unread/read/read-all）。

`tests/Feature/NotificationTest.php:103` `test_index_returns_all_with_kind_and_read_at` 断言 JSON 结构（`$res->json()`、`assertCount(2,...)`、`json('0.read_at')`）——改 view 后需重写。

`layouts/app.blade.php` 是全屏菜单导航式（右上角汉堡 → 全屏菜单 nav），无顶部栏。菜单 nav 在 :66–107，"个人中心"链接在 :83。

### 改法

**P2.1 controller 改返回 view**（`NotificationController::index`）
```php
public function index(Request $request)
{
    $notifications = $request->user()->notifications()
        ->orderByDesc('created_at')
        ->limit(20)
        ->get();

    return view('notifications.index', [
        'notifications' => $notifications,
        'unreadCount' => $notifications->filter(fn ($n) => is_null($n->read_at))->count(),
    ]);
}
```
- 不再做 `map` 成数组——直接传 Eloquent 集合给 Blade，模板里读 `$n->data['title']` 等。
- 保留 `unread`/`markRead`/`markAllRead` 三个 AJAX 端点不动。

**P2.2 新建 `resources/views/notifications/index.blade.php`**
```blade
@extends('layouts.app')
@section('title', '通知')
@section('content')
<div class="max-w-3xl mx-auto px-6 py-16">
  <p class="label-caption text-accent mb-4">NOTIFICATIONS</p>
  <div class="flex items-center justify-between mb-10">
    <h1 class="font-display text-display-lg font-black text-ink">通知</h1>
    @if($unreadCount > 0)
      <form method="POST" action="{{ route('notifications.read-all') }}" x-data>
        @csrf
        <button type="submit" class="label-caption text-accent hover:opacity-70">全部标为已读 ({{ $unreadCount }})</button>

  @forelse($notifications as $n)
    <a href="{{ $n->data['url'] ?? '#' }}"
```

## 4. 不做（明确排除）

- **`confirm-password` 路由**（敏感操作确认）：Breeze stub，与改密码无关，不接。
- **通知未读实时 badge**：菜单入口先静态，实时轮询留增强。
- **通知单条 AJAX 标已读**：列表页用"全部已读"表单即可，单条点击直接跳转档案（跳转时后台可另加 markRead，本期不做）。

- **`notifications.{id}` 改 route model binding**：D 项（轻微），本期不做。
